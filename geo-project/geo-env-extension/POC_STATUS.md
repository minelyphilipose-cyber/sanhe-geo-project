# GEO 指纹浏览器分发 PoC 状态

本文档记录当前 AdsPower 环境内 PoC 扩展的三平台适配状态、验收点和生产化缺口。

## 当前流程

```text
后台/本地助手创建半自动分发任务
-> 本地助手启动指定 AdsPower 环境
-> 环境内 PoC 扩展领取当前环境任务
-> 扩展填充前做账号一致性校验
-> 打开平台发布/编辑页
-> 填充标题和正文
-> 读回校验通过后 ack 后台任务
-> 运营人工核对并发布
```

扩展不会自动点击发布。

## 今日头条

已验证：

- AdsPower 环境重启后登录态保持。
- 能进入文章发布页。
- 标题和正文命中不同元素。
- 正文不会误填到标题框。
- 填充后读回校验通过。
- 可读取头条账号 ID 或名称并做一致性校验。

注意：

- 如果任务携带期望账号 ID 或名称，自动领取应从 `mp.toutiao.com` 平台页触发。
- 账号不一致、读不到 ID 等情况会拒绝填充并通知本地助手失败。

## 知乎

已验证：

- 能进入写文章页并填充标题、正文。
- 当前账号名称可从头像 alt、`/people/{urlToken}`、页面脚本、storage 中探测。
- 可用系统自媒体账号名称做一致性校验。

注意：

- 知乎编辑器对打开路径和窗口布局较敏感。当前扩展对知乎任务采用新开目标页，不复用当前 tab，让平台完成自身中间跳转和布局初始化。
- 正文填充采用纯文本输入路径，避免直接 HTML 注入破坏 Draft.js 状态。

## 小红书

已验证：

- 能识别创作服务平台已登录状态，不再把“退出登录”误判为登录入口。
- 能从发布页进入“写长文”。
- 能点击“新的创作”进入编辑器。
- 能填充标题和正文。
- 可从 `.d-topbar-default .user-info .name-box` 读取账号名称，例如 `potato00fa`。
- 可用系统自媒体账号名称做一致性校验。

注意：

- 小红书普通“上传图文”需要图片素材，纯文章内容当前走“写长文”路径。
- 页面点击使用 Chrome debugger 权限模拟真实鼠标点击，用于处理小红书 tab/按钮的 React 事件绑定。

## 当前 PoC 限制

- 本地助手每个环境只保留一个待处理任务，不是正式队列。
- 本地助手仍通过后台 Access Token 创建任务，生产版应改为后台签发给本地助手的受限会话。
- `chrome-extension://` 来源目前在本地助手 CORS 中整体放行，生产版应限定扩展 ID。
- 知乎和小红书账号校验主要依赖名称或页面标识探测，生产版最好在绑定时固化平台唯一标识。
- 扩展仍为手动加载未解压目录，生产版需要安装、升级、版本检查和灰度策略。
- 内容格式只保证基础标题/正文，图片、封面、标签、合集、声明、投放广告等平台字段未完整自动化。
- 不处理平台风控弹窗、首次引导、草稿冲突、异常验证码等复杂状态。

## 生产化下一步

1. 后台 UI 改造：从后台正式入口创建任务、打开环境、显示任务状态，不再要求运营打开本地助手页面。
2. 环境绑定模型：落库 `browser_environment`、`browser_environment_account`、`local_agent_device`、`local_agent_session`。
3. C2 安全：本地助手和后台做设备配对、短期会话、请求签名、权限收敛和日志脱敏。
4. 任务队列：支持同一环境多任务排队、超时恢复、幂等领取、人工处理状态。
5. 扩展运维：批量安装、自动更新、版本兼容检查。
6. 平台字段完善：封面、图片、标签、合集、声明、广告、定时发布等平台字段逐步补齐。
