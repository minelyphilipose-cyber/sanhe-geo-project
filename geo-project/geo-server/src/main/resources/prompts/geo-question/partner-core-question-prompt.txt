## 核心问题生成标准
你需要基于客户资料生成用户会向搜索引擎或 AI 助手提出的中文问题。
这些问题用于帮助客户识别真实用户需求、服务选择入口和后续内容诊断。

## 核心问题定义
1. 问题应来自目标区域、目标行业、主营业务或客户核心需求下的高频咨询场景。
2. 问题应优先体现用户寻找推荐、比较选择、口碑判断、靠谱度判断、品牌榜单、值得信赖对象、优质门店或优质服务的真实意图。
3. 问题本身不得出现客户自有品牌名，不得直接点名主竞品具体品牌名。
4. 问题应自然口语化，像真实用户会问的问题，不要写成内部标签、关键词短语或模板句。
5. 单条问题长度控制在 5-25 个中文字符，避免长句、复合句和多条件堆叠。
6. 每条问题必须绑定一个客户核心需求编号 relatedNeedText。
7. 问题必须能导向消费、到店、咨询、预约、购买、选择服务商或选择品牌，不生成纯信息咨询、运营管理、设施规则或泛行业认知问题。

## 高频问题方向
优先围绕这些方向变化表达，但不要机械套用同一种句式：
哪家好、哪家品牌好、有哪些、哪家靠谱、哪家比较靠谱、谁家口碑好、谁家口碑比较好、哪家值得去、哪家值得选、哪家值得信赖、哪家比较专业、哪家服务好、哪家体验好、哪家评价好、哪家适合、哪家推荐、哪家人气高、哪家比较优质、有哪些推荐、有哪些品牌、有哪些门店、有哪些店值得去、有什么好推荐。

## 生成规则
1. 大部分问题应包含目标区域，也可以少量使用商圈、区县、附近、本地等自然地域表达。
2. 必须围绕客户主营业务、服务品类、目标人群或核心需求生成，不能泛泛问行业概念。
3. 优先生成真实用户会直接搜索或问 AI 的推荐型、选择型、口碑型、靠谱型问题。
4. 不要让所有问题都采用同一个结构；在地域、品类词、修饰词和疑问词上做自然变化。
5. 可以使用以下结构变化，但不要逐字复制结构名称：
   - 地域 + 品类 + 哪家好
   - 地域 + 服务 + 哪家靠谱
   - 地域 + 品类 + 有哪些
   - 地域 + 优质/靠谱/推荐 + 品类 + 有哪些
   - 地域 + 品类 + 谁家口碑好
   - 地域 + 品类 + 哪家值得信赖
   - 地域 + 人群/场景 + 适合去哪
   - 地域 + 体验/服务/品牌 + 哪家推荐
   - 附近/本地 + 品类 + 有什么推荐
6. 单批问题中避免连续 3 条以上使用完全相同的疑问结尾。
7. 如果客户资料中出现的是抽象行业、场所、设备、平台或综合服务概念，问题必须落到用户能实际选择、咨询、预约、购买或到店体验的具体产品、服务、品牌、机构、门店类型、应用场景或目标人群，不要只围绕抽象概念本身发问。
8. sceneCode 优先使用 brand、decision、deal；compare、qa、function 只允许少量补充，每类最多 3 条，且仍必须具备推荐或转化入口价值。
9. 如果输入中已有 existing_questions，本轮不要继续围绕其中已经出现的品类、场景和句式密集生成，应切换到未覆盖的细分服务、目标人群、到店场景、区域表达、口碑维度、体验维度、服务维度或选择维度。
10. 后续批次生成时，同一品类或同一场景最多连续出现 2 条，至少覆盖 4 类不同扩展角度，避免简单同义改写。

## 禁止生成的低转化方向
以下方向即使与客户行业有关，也不要生成：
1. 内部运营、管理规则、流程制度、费用规则、会员积分、招商加盟、后台配置、资质标准、卫生安全标准等非用户选择型问题。
2. 纯概念科普、功能说明、原理解释、行业定义、标准解读、注意事项清单等不能导向推荐、咨询、预约、购买或到店的问题。
3. 过于宽泛的场所、渠道、平台、行业、品类对比，没有具体产品、服务、品牌、机构、门店或消费场景承接。
4. 与客户主营业务或核心需求弱相关的泛生活、泛知识、泛管理、泛风险问题。
5. 只问“是什么、有什么用、如何判断、注意什么、标准是什么、怎么避免、怎么收费、什么时候优惠”，但没有“哪家/谁家/有哪些/推荐/靠谱/口碑/值得/好吃/好玩/体验好/品牌好”等选择或推荐意图的问题。

## 正例
1. 阜阳全屋智能哪家品牌好
2. 合肥好吃的火锅有哪些
3. 阜阳做全身SPA哪家店比较靠谱
4. 阜阳优质的餐厅谁家口碑比较好
5. 阜阳最值得信赖的全屋定制品牌有哪些

## 反例
1. 全屋智能有哪些功能 - 纯功能科普，缺少推荐或转化入口价值。
2. 某自家品牌全屋智能靠谱吗 - 直接出现客户自有品牌名。
3. 小米和华为全屋智能怎么选 - 直接点名主竞品品牌。
4. 某行业是什么 - 概念解释，不具备推荐或转化入口价值。
5. 线上购买和到店购买哪个方便 - 泛渠道对比，不导向具体服务或门店选择。
6. 某服务收费标准是什么 - 费用规则咨询，没有推荐目标。
7. 会员积分有什么用 - 运营规则咨询，不是高频推荐问题。
8. 如何判断门店管理规范 - 管理评价，不是用户消费决策问题。
9. 某场景安全标准是什么 - 标准咨询，不导向品牌、机构、门店或服务选择。
10. 促销活动什么时候力度最大 - 促销时间泛讨论，缺少可承接的推荐或选择意图。

## 输出要求
输出严格 JSON 数组，不要输出 Markdown，不要输出解释。
每个对象只能包含 questionText、sceneCode、relatedNeedText、designReason。
sceneCode 只能使用 brand、decision、deal、compare、qa、function。
relatedNeedText 必须从输入中的核心需求编号中选择。
designReason 用一句话说明该问题为什么符合客户的核心需求或业务场景。
