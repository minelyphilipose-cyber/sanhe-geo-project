# 自媒体分发本地助手 v1 交付说明

本文档用于交付“指纹浏览器环境隔离 + 本地助手 + 环境内扩展”的半自动自媒体分发链路。v1 只负责打开对应 AdsPower 环境、领取任务、填充标题和正文，由运营人工核对后发布；不实现自动点击发布。

## 背景

旧方案尝试通过装载 Cookie 切换平台登录态，已在今日头条验证失败。头条登录态依赖 IndexedDB、CacheStorage、Service Worker 等完整站点数据，单独恢复 Cookie 不能稳定恢复登录。

当前采用完整浏览器环境隔离：

```text
后台选择文章和平台账号
-> 本地助手启动绑定的 AdsPower 环境
-> 环境内扩展领取任务
-> 自动打开平台编辑页并填充标题/正文
-> 运营人工核对并发布
```

## 角色分工

- 后台：保存品牌、账号、指纹浏览器环境绑定关系，创建半自动分发任务。
- 本地助手：运行在运营电脑上，负责调用 AdsPower Local API、保存 C2 会话、临时缓存待领取任务。
- 环境内扩展：安装在 AdsPower 环境中，负责读取登录状态、领取任务、填充页面。
- AdsPower：保存平台完整登录态，一个品牌默认绑定一个 AdsPower 环境，账号可继承品牌默认环境。

## 首次准备

### 1. 启动本地助手

开发环境下：

```powershell
cd D:\code\sanhe-geo-project\geo-project\geo-local-helper
npm install
Copy-Item config.example.json config.local.json
npm start
```

本地助手默认地址：

```text
http://127.0.0.1:17891/
```

生产交付包完成前，运营电脑仍按上述方式启动；后续会固化为一键启动包。

### 2. 绑定本地助手

绑定入口在后台：

```text
右上角头像 -> 个人中心 -> 本地助手
```

操作步骤：

1. 打开本地助手页面。
2. 在本地助手页面生成一次性配对码。
3. 回到个人中心，在“本地助手”模块输入配对码。
4. 点击“绑定本机”。
5. 绑定成功后，个人中心会显示“本地助手已绑定”。

配对是当前运营账号与当前电脑之间的信任关系。重新绑定会替换当前账号原有的活跃助手会话。

### 3. 配置 AdsPower 连接

入口同样在：

```text
右上角头像 -> 个人中心 -> 本地助手
```

填写：

- AdsPower API 地址：默认 `http://localhost:50325`
- AdsPower API Key：当前运营电脑使用的 AdsPower API Key

AdsPower API Key 属于本机助手配置，不在品牌分发页面填写。

### 4. 安装环境内扩展

在 AdsPower 环境中打开：

```text
chrome://extensions
```

启用开发者模式，加载已解压扩展：

```text
D:\code\sanhe-geo-project\geo-project\geo-env-extension
```

扩展安装在 AdsPower 环境内，不安装在普通后台浏览器里。扩展应保持“打开平台页后自动领取并填充”开启。

## 品牌环境配置

入口：

```text
品牌详情 -> 指纹浏览器环境
```

配置内容：

- 环境名称：运营可识别的名称，例如“得闲_adspower”
- 环境标识：系统内部标识，例如 `geo_b`
- AdsPower 环境 ID：AdsPower profile id，例如 `k1cvxpjx`

同一品牌默认使用一个 AdsPower 环境。新增头条、知乎、小红书账号时，默认绑定当前启用的品牌环境；特殊账号后续可以单独调整绑定。

## 自媒体账号登录状态

账号登录状态由 AdsPower 环境内扩展上报。运营不需要手动填写平台账号 ID。

典型状态：

- 环境已登录：可以分发。
- 待首次登录：需要打开环境登录并自动上报。
- 需重新登录：平台登录态失效，需要在 AdsPower 环境内重新登录。
- 账号不一致：当前环境登录账号和系统绑定账号不一致，需要重置账号校验后重新上报。
- 未绑定环境：需要到品牌详情绑定指纹浏览器环境。

## 日常发文流程

1. 进入文章分发页面。
2. 选择已就绪文章。
3. 点击目标平台图标或“打开环境并填充”。
4. 系统检查本地助手、AdsPower API Key、品牌环境、账号绑定和登录状态。
5. 检查通过后启动 AdsPower 环境。
6. 环境内扩展自动领取任务并填充标题/正文。
7. 运营在平台编辑页人工核对。
8. 运营手动发布或保存草稿。

## 常见提示

| 提示 | 处理位置 | 处理方式 |
| --- | --- | --- |
| 本地助手未就绪 | 个人中心 > 本地助手 | 启动本地助手并完成配对 |
| 本地助手配对已失效 | 个人中心 > 本地助手 | 重新生成配对码并绑定 |
| 缺少 AdsPower API Key | 个人中心 > 本地助手 | 填写 AdsPower API Key 并保存 |
| 品牌未配置指纹浏览器环境 | 品牌详情 > 指纹浏览器环境 | 新增并启用 AdsPower 环境 |
| 自媒体账号未绑定环境 | 品牌详情 > 自媒体账号 | 绑定到品牌环境 |
| 需重新登录 | AdsPower 环境 | 打开环境完成平台登录 |
| 账号不一致 | 品牌详情 > 自媒体账号 | 确认账号后重置账号校验，再由扩展上报 |
| 本地助手请求签名无效 | 个人中心 > 本地助手 | 重新配对本地助手 |
| 检测到重复请求 | 当前页面 | 稍后重试，避免连续重复点击 |

## 当前边界

- v1 不自动点击发布按钮。
- v1 不做扩展批量安装和自动更新。
- v1 暂不支持同一运营账号同时绑定多台活跃本地助手。
- v1 暂不做多人多机器流转。
- v1 仍保留旧 Cookie 凭证数据用于审计和回滚，但新环境模型账号的任务执行不再依赖旧 Cookie。

## 交付前检查

- 本地助手能启动，`/health` 返回 `paired=true`。
- 个人中心能显示当前本地助手在线状态。
- AdsPower API Key 已保存。
- 品牌详情已配置指纹浏览器环境。
- 平台账号状态为“环境已登录”。
- 头条、知乎、小红书各至少完成一次填充验证。
- C2 安全脚本 `npm run security:c2` 返回 `C2_SECURITY_CHECK=ok`。
