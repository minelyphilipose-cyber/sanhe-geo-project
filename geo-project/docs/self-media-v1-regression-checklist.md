# 自媒体分发 v1 回归清单

本文档用于每次修改本地助手、环境扩展、品牌环境配置、分发弹窗或账号状态逻辑后回归。除特别说明外，所有场景都不应自动发布，只允许填充到平台编辑页或草稿页，由运营人工确认。

## 1. 主链路回归

### 1.1 今日头条

- 前置：账号状态为“环境已登录”。
- 操作：后台点击头条图标或“打开环境并填充”。
- 期望：
  - 启动正确 AdsPower 环境。
  - 页面进入头条文章编辑器。
  - 标题和正文填充到不同元素。
  - GEO 提示填充成功。
  - 不自动点击发布。

### 1.2 知乎

- 前置：账号状态为“环境已登录”。
- 操作：后台点击知乎图标或“打开环境并填充”。
- 期望：
  - 启动正确 AdsPower 环境。
  - 页面进入知乎写文章页面。
  - 标题和正文填充成功。
  - GEO 提示账号校验通过并填充成功。
  - 不自动点击发布。

### 1.3 小红书

- 前置：账号状态为“环境已登录”。
- 操作：后台点击小红书图标或“打开环境并填充”。
- 期望：
  - 启动正确 AdsPower 环境。
  - 页面进入小红书图文/长文编辑器。
  - 标题和正文填充成功。
  - 小红书页面允许出现 Chrome 调试横幅。
  - 不自动点击发布。

## 2. 调试权限回归

- 头条：不应出现 Chrome debugger 调试横幅。
- 知乎：不应出现 Chrome debugger 调试横幅。
- 小红书：允许出现 Chrome debugger 调试横幅，因为关键点击需要真实点击。

## 3. 本地助手 C2 安全回归

在 `geo-project/geo-local-helper` 执行：

```powershell
npm run security:c2
```

期望输出包含：

```text
C2_SECURITY_CHECK=ok
PASS valid_signed_request_accepts status=200
PASS expired_timestamp_rejected status=401
PASS wrong_signature_rejected status=401
PASS wrong_session_access_rejected status=401
PASS nonce_replay_rejected first=200 second=409
```

异常场景要求：

- 过期时间戳被拒绝。
- 错签被拒绝。
- 错 session access 被拒绝。
- nonce 重放返回 409。
- 吊销 session 后，后台分发页提示重新配对本地助手。

## 4. 登录状态回归

### 4.1 首次登录登记

- 前置：账号环境绑定存在，`login_status=unknown`。
- 操作：在 AdsPower 环境登录平台账号，打开平台首页或可稳定读取账号身份的页面。
- 期望：
  - 扩展自动上报或点击上报后，后台写入 expected 账号信息。
  - 状态变为“环境已登录”。

### 4.2 登录过期

- 前置：平台账号退出登录或登录态失效。
- 操作：打开环境并上报登录状态。
- 期望：
  - 状态变为“需重新登录”或对应登录异常。
  - 分发页禁止填充，并提示去 AdsPower 环境重新登录。

### 4.3 账号不一致

- 前置：环境中登录另一个平台账号。
- 操作：上报登录状态或尝试填充。
- 期望：
  - 状态变为“账号不一致”。
  - 分发页禁止填充。
  - 提示到品牌详情重置账号校验后重新上报。

### 4.4 重置账号校验

- 前置：账号状态为 `mismatch`。
- 操作：在品牌详情点击“重置账号校验”，再用正确账号上报。
- 期望：
  - 状态允许从 `mismatch` 回到 `unknown`。
  - 正确账号重新上报后变为“环境已登录”。

## 5. 前置设置缺失回归

| 场景 | 操作 | 期望提示 |
| --- | --- | --- |
| 未配对本地助手 | 点击分发 | 提示到“个人中心 > 本地助手”完成配对 |
| 本地助手未启动 | 点击分发 | 提示启动本地助手 |
| 未配置 AdsPower API Key | 点击分发 | 提示到“个人中心 > 本地助手”配置 AdsPower |
| 品牌未配置环境 | 点击分发 | 提示到“品牌详情 > 指纹浏览器环境”配置 |
| 账号未绑定环境 | 点击分发 | 提示到“品牌详情 > 自媒体账号”绑定 |
| 环境被禁用 | 点击分发 | 禁止填充并提示环境不可用 |
| 账号不是环境已登录 | 点击分发 | 禁止填充并提示对应处理位置 |

所有提示应使用中文，并尽量给出页面位置或跳转按钮。

## 6. 任务复用与重复点击回归

- 场景：同一篇文章、同一平台账号重复点击“打开环境并填充”。
- 期望：
  - 不创建重复业务任务。
  - 可复用现有活跃任务重新填充。
  - 不出现 `fill token used or expired`。
  - 如果账号状态已变成 `mismatch/login_required`，复用也必须被拦截。

## 7. Service Worker 回收回归

操作：

1. 打开 `chrome://extensions`。
2. 找到环境扩展。
3. 打开扩展详情或 Service Worker 检查窗口。
4. 在 Chrome 任务管理器中结束该扩展 Service Worker。
5. 回到后台重新点击分发。

期望：

- 任务状态能恢复。
- 同一任务不会被重复处理成多个后台任务。
- 扩展重新唤醒后可以继续领取并填充。

## 8. 旧 Cookie 凭证隔离回归

- 前置：某账号旧 `self_media_cookie_credential` 仍存在或为 ACTIVE。
- 操作：该账号已绑定新 browser environment 模型后发起分发。
- 期望：
  - 任务执行只依据 `browser_environment_account.login_status`。
  - 不因为旧 Cookie 凭证 ACTIVE 而绕过环境登录状态。

## 9. 本地助手交付回归

- 本地助手能启动。
- `/health` 返回 `ok=true`。
- 配对成功后 `paired=true`。
- 个人中心显示最近在线时间为本地时区。
- AdsPower API Key 保存后不在页面明文展示。
- 吊销后分发页提示重新配对。
