# AdsPower 环境绑定失效排查（2026-10-08）

## 结论与证据边界

用户描述：生产中约十天需要在本系统重新导入、绑定同一个 AdsPower 环境；原环境和自媒体编辑页仍能打开，但不能填充，扩展提示未绑定；出问题前环境通常处于关闭状态，扩展约为 0.2.8。

该现象与**扩展后台授权到期且未能续期**的链路高度一致。当前代码和默认配置能够解释这种行为；尚未读取生产实际配置、当次失效日志或旧扩展会话记录，因此不能把某次生产事件写成已经实证确认。

同时，本机实证发现并修复了另一处问题：扩展会话保存 UTC 时间，自动化就绪检查却按服务本地时间比较，导致刚通信的扩展被误判离线，临近到期时还可能被提前判为未绑定。此问题影响状态显示及恢复引导，不能直接解释扩展内部清除授权。

## 为什么浏览器能打开，却不能填充

| 链路 | 修复前规则 | 失效时的表现 |
| --- | --- | --- |
| AdsPower 环境与本系统环境记录 | 按稳定的 `providerProfileId` 和环境标识连接，本系统未设置十天有效期 | 浏览器可以继续打开 |
| 浏览器扩展与后台授权 | 默认 7 天；剩余不超过 1 天时，成功调用续期接口才延长有效期 | 到期后无法请求运行配置、签名、填充令牌 |
| 本地助手配对 | 30 天；剩余不超过 7 天时续期，助手每 6 小时检查 | 与扩展授权是不同会话，助手在线不代表扩展授权有效 |
| 自媒体网站登录 | 由各平台登录会话决定 | 本轮搜狐登录仍正常，与扩展后台授权分别核对 |

修复前源码链路：

1. `application.yml` 使用 `EXTENSION_LONG_TOKEN_TTL_DAYS:7`、`EXTENSION_LONG_TOKEN_SLIDE_RENEW_THRESHOLD_DAYS:1`。
2. `ExtensionSessionService.validateAndMaybeRenew` 先校验授权未过期，再判断是否处于续期窗口；授权过期后不能通过该入口恢复。
3. `geo-env-extension/service-worker.js` 心跳会调用续期接口；浏览器环境关闭时扩展不能运行这个过程。7 天不是无条件从最后一次使用重新计算：如果使用时间未进入最后 1 天的窗口，也不会延长授权。
4. 后台返回 `extension token expired/invalid` 后，扩展清除当前失效会话，后续弹窗显示“未绑定后台”，填充流程停止。
5. `BrandDetail.vue` 的“导入并启用”在更新已有环境记录后，还会调用“打开环境并绑定扩展”。因此重新导入能恢复，实际恢复动作通常是获取了新的扩展授权，不是浏览器实例被修好。

Chrome 扩展后台是事件驱动的 service worker；普通定时器不能保证续期，后台周期任务应使用 alarms。当前源码已使用每分钟 alarm 并在启动时创建。具体行为参考 [Chrome 后台事件说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/service-worker-events) 和 [alarms 文档](https://developer.chrome.com/docs/extensions/reference/api/alarms)。

AdsPower 的环境 ID 和浏览器调试连接是不同数据：其启动、状态接口按环境 ID 返回当前调试连接。参见 [启动浏览器接口](https://localapi-doc-zh.adspower.net/docs/Exqfpw) 和 [浏览器状态接口](https://localapi-doc-en.adspower.com/docs/YjFggL)。本地助手目前缓存连接 2 分钟，操作入口遇到旧连接错误会刷新重试；这与扩展显示未绑定的授权问题需分别诊断。

## 生产进一步确认与恢复方式

下次发生问题时，在重新绑定前记录旧扩展会话的 `bound_at / last_seen_at / expires_at / status / extension_version`，核对生产的两个 `EXTENSION_LONG_TOKEN_*` 配置，以及续期接口最后成功与首个过期响应的时间。只需要元数据，不导出 token、哈希、HMAC 密钥或网站 Cookie。

- 若授权尚有效但扩展不活跃：打开已有 AdsPower 环境，检查扩展启用及后台网络通信，刷新状态。
- 若授权已过期：对已有环境使用系统“打开并绑定扩展”入口恢复，无需先删除或重新导入浏览器实例。
- 若环境一直打开仍过期：重点查实际安装版本、alarm 是否存在、后台接口失败、网络阻断、会话被撤销或切换后台配置。
- 若重新配对本地助手或换电脑后出现绑定异常：另查环境机器归属与助手会话，不与扩展到期混为一类。

用户随后同意实施授权 30 天、按使用自动续期、网络异常保留授权三项，并排除新增重新绑定入口。实现与测试结果见下节；生产仍未部署。超过新的授权期限后仍需重新授权，已过期的旧会话不能靠改默认天数自动恢复。

## 后续已批准的授权修复（2026-10-08）

- 后端配置默认期限调整为 30 天，取消“只在到期窗口内续期”的判断。成功调用授权刷新接口时，后端用 UTC 自然日限制当天最多续期一次；到期时间延至该次有效连接起 30 天。
- 数据库更新同时校验状态为 active、授权尚未过期、尚未完成当天续期。使用已有到期字段推算每日边界，不新增数据表或字段；并发请求只会有一个实际续期，其他请求读取最新到期时间。令牌、会话 ID 和环境绑定不轮换，超过 30 天闲置导致的过期仍按原认证规则处理。
