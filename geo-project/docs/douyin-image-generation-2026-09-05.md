# 抖音文章生图：开发与效果测试

本次新增 Seedream 图片生成配置、文章生图任务和效果预览。代码中的自动生图默认值为关闭；本地效果已确认，用户已在 application-prod.yml 中开启自动生图，当前开发与生产配置均为开启，待部署服务器测试。新增模型配置、生成和应用图片均不等于开启自动发布。

## 功能边界

本次生图业务变更仅适用于 `self_media` 下的 `douyin` / `douyin_image_text` 文章。其他渠道不显示生图入口，后端列表、生成、重试和应用接口均拒绝非抖音图文；自动生图开关即使开启也跳过其他渠道。排队期间文章切换渠道时停止生图，不应用图片。后续按用户要求另行修复了自媒体手动发布的预占额度替换，适用于各自媒体平台，详见下文。

公共代码仅增加隔离措施：抖音专属生成素材不进入公共随机封面/插图池；图片模型不进入文本模型候选；原调度器保持为默认，生图使用独立调度器。现有素材的新字段默认为 NULL，原有选图、正文生成及其他渠道排期发布流程保持原逻辑。本次不调整其他渠道的提示词、图片数量、水印或发布方式。

## 测试前配置

1. 在测试环境部署代码并执行 Flyway V370。不要跳过迁移直接启动旧数据库上的新代码。
2. 复用现有 `ObjectStorageService` 统一入口和 `geo.storage.provider` 配置：本地 MinIO、生产 COS。不增加生图专用存储路由或额外 COS 配置要求，不把临时豆包图片链接当成永久素材。
3. 确认 `geo.public-base-url` / `APP_PUBLIC_URL` 和素材签名密钥配置正确，生成素材通过现有品牌素材接口预览与下载。
4. 在大模型配置中新增：用途「图片生成 · 豆包 Seedream」，平台编码 `doubao_image`，协议自动为 `OPENAI_IMAGE`。
   - 接口地址：`https://ark.cn-beijing.volces.com/api/v3`
   - 模型 ID：`doubao-seedream-5-0-260128`
   - 密钥：页面输入后加密保存，或引用 `env://ARK_API_KEY`；二选一。
   - 启用总开关；不参与正文、售前或问题生成。
5. 还需至少一个已启用的文章文本模型，用于提炼分图文案。图片模型不承担这一步。

## 效果测试

在内容执行页打开一篇抖音文章的详情，点击「生图测试」。默认4张，可以选择1—6张；每组使用同一种视觉方向。自动风格从编辑杂志、场景摄影、立体材质、极简信息、叙事插画和纸艺拼贴中选择，并避开文章主体最近三次使用的风格。

建议用同一篇文章分别选择两种风格生成测试组。生成过程持久化，关闭弹窗不会取消任务；重新打开可看进度。列表每8秒刷新活动任务。失败可重试未完成图片，已保存的页面不重新调用模型。网络响应不确定时可能已产生上游费用，无法承诺上游调用恰好一次。

图片请求显式使用 `watermark:false`，尺寸 `1440x2560`（9:16、2K级），每次生成一页，以服务端页码保持顺序。接口和具体输出效果需使用已开通账号进行真实验证。无 OCR、画面审核或自动文字质量检查；仅验证分图响应结构、文件格式/大小、素材归属和任务状态。

测试图片按当前环境配置存入 MinIO 或 COS，归属于文章主体品牌，带 `source_article_id`，不进入公共封面和插图随机候选池。第一张作为应用后的封面。点击「应用这一组」生成新的文章版本，移除原有图片并按顺序插入整组新图，不改写文章文字。已有发布任务或已经发布的文章只允许测试预览，禁止替换正在执行的发布内容。文章版本改变后，旧测试组不能再应用。

## 发布衔接

应用后的文章保存 `douyin_image_batch_id`。创建抖音发布快照时完整读取该组1—6张图片的原始顺序，不随机抽取、不混入旧素材；版本不匹配或素材失效会报错，不能回退到旧图片。已有发布快照不会被本功能改写。

只有效果确认并得到上线决定后，才可在生产环境显式设置 `geo.douyin-images.auto-enabled=true`。默认 `false`，本地开发配置为 `true`。该开关同时控制批量生成、模板单篇生成、AI预览后保存和新的月度计划项。普通AI文章正文入库时，抖音图文跳过旧随机封面和插图，在同一事务内创建生图任务；图片完成后自动生成新版本并应用。月度计划等待生图、存储与应用完成，再创建发布任务；图片失败时暂停该项排期并保留文章。处理方式是在文章详情重试图片任务，完成后重试对应排期失败项。旧的历史批次兼容路径维持原逻辑，上线时应确认目标计划使用 V369 持久化计划项。

独立的单线程生图调度器每10秒领取一个任务，防止耗时生图占用发布调度线程。任务有数据库领取保护和执行令牌；超时/进程中断会标记失败，等待明确重试。第一版逐页执行，吞吐量以效果测试为主；需要更大规模时再调度并发，不以文本模型的 TPM 指标计算图片费用。

## 主要代码

- `DouyinImagePrompts`：分图和生图提示词、视觉方向。
- `ArkImageClient`：图片接口、显式关闭水印、下载与文件边界校验。
- `DouyinArticleImageService`：权限、主体解析、持久化任务、统一对象存储、重试和应用。
- `DouyinArticleImageController`：文章范围内的列表、生成、重试、应用接口。
- `SelfMediaPublishMaterialSelectionService`：生成图片优先且严格保序。

当前不包含实际密钥，未连接服务器执行数据库迁移或部署，未自动发布测试内容；生产生图开关已按用户确认纳入待部署配置。
